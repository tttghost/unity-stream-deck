Stream Deck SDK 쉽게 이해하기

Elgato Stream Deck SDK를 처음부터 이해하고, 현재 UnityStreamDeck 프로젝트의 구조와 문제 지점을 연결해서 보는 문서입니다.

한 문장 요약
Stream Deck 플러그인은 액션을 등록하고, Property Inspector는 액션 설정을 입력하며, Unity 패키지는 별도의 localhost 통신으로 Unity Editor를 제어합니다.

1. 전체 구조

Stream Deck 앱 ↔ Stream Deck 플러그인 ↔ Unity 패키지 ↔ Unity Editor

Stream Deck 앱버튼 배치, 제목, 프로필, 액션 설정 저장Elgato 프로그램

2. 액션이란?

Stream Deck에 배치하는 버튼 하나가 액션입니다. 예를 들어 플레이, 정지, 씬 열기, 게임 뷰 복사가 각각 액션입니다.

@action({ UUID: "com.tttghost.stream-deck-unity.scene-open" })
export class OpenSceneAction extends SingletonAction<Settings> {
  override async onKeyDown(ev: KeyDownEvent<Settings>) {
    const sceneName = ev.payload.settings.argument;
    // Unity로 scene.open 명령 전송
  }
}

액션의 UUID는 manifest의 UUID와 반드시 같아야 합니다. 이 UUID가 액션 종류를 구분합니다.

3. manifest.json은 무엇인가?

manifest는 Stream Deck에 “이 플러그인에는 어떤 액션이 있는가?”를 알려주는 목록입니다.

{
  "Name": "Unity",
  "UUID": "com.tttghost.stream-deck-unity",
  "CodePath": "bin/plugin.js",
  "Actions": [{
    "Name": "씬 열기",
    "UUID": "com.tttghost.stream-deck-unity.scene-open",
    "PropertyInspectorPath": "property-inspector/scene-open.html"
  }]
}

CodePath는 컴파일된 플러그인 진입점이고, PropertyInspectorPath는 해당 액션을 선택했을 때 보이는 설정 화면입니다.

4. Property Inspector란?

Stream Deck 앱 오른쪽에 나타나는 입력 화면입니다. 씬 이름이나 메뉴 경로를 입력하는 HTML 화면이 여기에 해당합니다.

공식 문서의 권장 방식은 sdpi-components입니다.

<script src="https://sdpi-components.dev/releases/v4/sdpi-components.js"></script>

<sdpi-item label="씬 이름 또는 경로">
  <sdpi-textfield setting="argument"></sdpi-textfield>
</sdpi-item>

여기서 setting="argument"는 “이 입력값을 액션 설정의 argument라는 이름으로 저장하라”는 뜻입니다.

중요: 버튼 상단의 제목과 Property Inspector의 입력값은 서로 다른 값입니다. 버튼 제목에 Main을 입력해도 씬 설정인 argument가 저장되는 것은 아닙니다.

5. 액션 설정은 어떻게 저장되는가?

액션마다 별도의 JSON 설정이 저장됩니다.

"Settings": {
  "argument": "Main"
}

플러그인은 버튼을 눌렀을 때 다음처럼 설정을 받습니다.

override async onKeyDown(ev: KeyDownEvent<Settings>) {
  const { argument = "" } = ev.payload.settings;
}

공식 문서에서는 설정을 저장할 때 ev.action.setSettings({...})를 사용하고, 설정을 읽을 때는 가능하면 이벤트의 ev.payload.settings를 사용하도록 설명합니다.

6. WebSocket은 두 종류로 나눠서 봐야 한다

통신SDK 사용 여부설명
Stream Deck 앱 ↔ 플러그인공식 SDK 사용@elgato/streamdeck가 연결과 이벤트를 관리합니다.
Property Inspector ↔ Stream Deck 앱공식 컴포넌트 권장sdpi-components가 설정 저장과 UI 연결을 처리합니다.
플러그인 ↔ Unity 패키지직접 구현Unity용 공식 Stream Deck SDK가 없으므로 localhost WebSocket을 직접 사용합니다.

따라서 Unity 연결용 WebSocket은 필요한 구조입니다. 문제가 된 것은 Property Inspector까지 수동 WebSocket으로 처리하면서 저장·복원 코드를 여러 번 겹친 부분입니다.

7. 현재 프로젝트에서 잘못 꼬였던 부분

  • Property Inspector가 직접 WebSocket을 열어 설정을 저장했습니다.
  • setSettings, sendToPlugin, localStorage, global settings 백업을 동시에 사용했습니다.
  • 입력값 복원 시 빈 payload가 기존 값을 덮어쓸 수 있었습니다.
  • 버튼 제목과 실제 액션 설정을 혼동하기 쉬웠습니다.
  • 설정 저장 로직과 Unity 경로 동기화 로직이 한 파일에 섞여 있었습니다.

현재 단순 입력을 받는 씬 열기, 메뉴 실행, 창 열기, 메서드 호출, 스크린샷, 게임 뷰 복사 액션은 공식 sdpi-textfield 방식으로 통일했습니다. 저장 경로 선택은 공식 sdpi-delegate가 sendToPlugin을 통해 플러그인에 요청하고, 플러그인이 Unity WebSocket을 호출합니다.

8. Unity 연결은 어떻게 동작하는가?

플러그인은 Unity 패키지가 열어 둔 localhost WebSocket에 JSON 명령을 보냅니다.

{
  "version": 1,
  "type": "unity.command",
  "command": "scene.open",
  "argument": "Main"
}

Unity 패키지는 이 명령을 받아 Unity 메인 스레드에서 Unity Editor API를 실행합니다. 반대로 Unity의 플레이 상태나 빌드 상태도 WebSocket으로 플러그인에 보낼 수 있습니다.

10. 앞으로 지켜야 할 규칙

  1. 단순 입력 액션은 직접 WebSocket 저장 코드를 만들지 않는다.
  2. 액션 변수는 버튼 제목과 분리해서 관리한다.
  3. 설정 저장소를 여러 개 만들지 않는다.
  4. 플러그인은 ev.payload.settings를 우선 사용한다.
  5. Unity와 통신하는 WebSocket과 Stream Deck 설정 저장 통신을 섞지 않는다.
  6. 새 액션을 만들면 manifest UUID, Property Inspector, Settings 타입, Unity 명령을 함께 확인한다.
